## 릴리스·배포 절차

- 운영 환경 파일·DB가 없는 worktree에서 버전 표시·문서·태그용 CHANGELOG 절을 검사하고 필수 CI를 통과시킨다.
- 검증한 merge source에 v1.6.0 태그를 발행하고 Release workflow의 CHANGELOG 기반 발행을 확인한다.
- 실제 운영 Compose 프로젝트·환경 파일·data/backups 마운트·포트를 유지하고, 검증 source와 이미지 ID를 고정한다.
- 기존 이미지 보존 → 운영 DB 사본 복원/이전 예행 → 앱 정지 → 검증 백업 → 새 이미지 기동 →
  health/장부 대사 → 재시작·재검증 순으로 진행한다. 쓰기 재개 후 자동 전체 DB rollback은 하지 않는다.
- 인증된 조회·새 월간 입력 화면·버전 표시를 확인한다. 배포 검증을 위해 실제 월간 요청서를 확정하거나
  운영 인원/잔액을 수정하지 않는다. 실제 인원·번호·키·비공개 경로는 공개 기록에 넣지 않는다.

격리 환경의 기존 버전 검사 3건, Ruff check/format, mypy app scripts, CHANGELOG 절 추출,
수정 문서 상대 링크 검사와 독립 검토를 통과했다. 의존성 lockfile은 변경하지 않았다.

릴리스 PR·v1.6.0 릴리스 노트에 최종 source, merge ref CI, 이미지, 백업·복원·운영 대사의
실제 결과를 연결한다. 계획을 운영 반영 완료로 표시하지 않으며 실패·미실행을 구분한다.
