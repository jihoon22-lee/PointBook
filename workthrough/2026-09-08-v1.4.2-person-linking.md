# v1.4.2 번호 없는 요청서와 기존 인원 연결

## 문제와 변경

소방서가 알 수 없는 외부 포인트 시스템의 번호를 월간 요청서 필수 입력으로 요구했다.
사용자 확인에 따라 포인트번호는 외부 시스템 신규 등록 시 발급되며 PointBook에서 생성하지 않는다.
기존 번호·장부 연결·전체 인원 동기화·공용 예외와 금액 계산은 유지한다.

- 기본 Excel v2는 포인트번호 없는 9열이다. 기존 v1 업로드는 유지하고 번호 없는
  제목 포함 붙여넣기를 지원한다. 사진 AI에는 없는 번호를 추정하지 않도록 명시한다.
- 번호 없는 행에 이름 또는 개인번호가 일치하는 후보를 표시하고 관리자가 명시적으로
  연결한다. 중복 이름·개인번호로 자동 병합하지 않는다. 선택한 인원의 현재 버전을
  확인해 마스터 정보로 보완하고 충전액·비고·원문은 유지한다. 이월 잔액은 다시 입력한다.
- 신규는 외부 번호 발급 전까지 서버 초안으로 보관하고 확정을 차단한다. 실제 번호를
  받은 뒤 검수에서 입력한다. 임시 번호나 임의 신규 계정을 만들지 않는다.
- 연결과 자동 저장은 원본 셀 오류를 보존한다. 명시적인 재검수에서만 해제하며,
  기존 검수 fingerprint·초안 버전·확정 재전송 보호를 유지한다.
- 앱 1.4.2와 README·CHANGELOG·사용/Excel/구조 안내·AGENTS 계약을 함께 갱신한다.
  DB 스키마·의존성 버전·운영 환경 설정 변경은 없다.

사용자 변경 계약과 #48 R03/R05/R06/R07/R17/R20/R22/R26 → WP02/08/09 → 이 PR의
source SHA·CI로 추적한다. 종료된 v1.4.0 이슈를 다시 종료 대상으로 삼지 않는다.

## 실제 검증

운영 환경 파일 없는 `/tmp/pointbook-person-linking` worktree, Python 3.13, uv.lock,
명시적인 임시 DATABASE_PATH와 합성 자료만 사용했다.

- 신규 HTTP 회귀: 번호 미발급 초안/확정 차단, 외부 번호 등록의 중복 제출, 동명이인 선택,
  비재직 복귀·누락 전환, 공용 연결, 오래된 후보 거부, 재연결 잔액 초기화,
  다른 행의 원본 오류 보존과 명시 재검수. XLSX/초안 포함 관련 45건 통과.
- 최종 추가 붙여넣기 매핑/열 오류 및 버전 포함 11건 통과.
- 전체 검사 중 723건 통과, 커버리지 93.47%. 동시 Docker 검사 중 1,000명 대시보드
  응답이 3초 기준을 0.06초 넘었다. 단독 커버리지 계측에서는 2.521초, 쿼리 9회로
  기존 기준을 충족했다. 해당 부분 계측 명령은 전체 커버리지 85% 기준 때문에 비정상
  종료했으며 전체 성공으로 기록하지 않는다. 최종 전체 결과는 PR CI를 기준으로 한다.
- 규모 검사 단독 재실행 200/1,000명 2건 통과. 기존 시간·쿼리 기준은 변경하지 않았다.
- Ruff check/format, mypy app scripts, 임시 DB Alembic upgrade/check 통과.
- pip-audit 취약점 없음. 기존 52개 커밋과 변경 파일 gitleaks 검사에서 탐지 없음.
- 격리 production Compose smoke: custom env/mount, 백업·복원·장부 대사·재시작 통과.
- 구버전 Chromium E2E 16건 통과(26.19초). v2 신규 번호 입력과 기존 인원 연결의
  자동저장·초안 재개·확정·보고서 대사를 포함한다. 초안 URL 변경을 navigation 완료로
  오인한 초기 테스트 대기를 실제 연결 결과 대기로 수정했다.
- 독립 검토에서 원본 오류 소거 경로를 발견해 수정했고 재검토에서 추가 결함 없음.

## 배포와 한계

사용자가 v1.4.2 버전업·최신 배포까지 승인했다. PR 필수 7개 CI와 Quality gate 통과 뒤
squash merge하고 기존 배포 스크립트의 백업·복원 예행·health·재시작·DB 대사를 적용한다.
배포 결과와 source SHA는 릴리스 기록으로 연결한다. 실제 사진·인원 자료는 공개 기록에 넣지 않는다.

Win7 Chrome 109·갤럭시 실기 전체 흐름과 실제 Gemini 호출은 미실행이다.
외부 포인트 시스템의 계정 등록·번호 발급을 자동화하지 않으며 번호 미발급 신규가 남으면
전체 월간 확정을 진행할 수 없다. 기존 인원 연결 뒤 팀·계급 변경이 필요하면 검수에서 수정한다.
