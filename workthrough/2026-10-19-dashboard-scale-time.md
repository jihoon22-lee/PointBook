# 대시보드 1000명 규모 응답 시간 단축

## 문제와 확정 범위

#86·#87 머지 뒤 main CI 두 번이 `test_workflow_scale[1000]`의 대시보드 응답 한도(3초)를
넘어 실패했다(3.076초·3.080초). Quality gate가 실패해 다음 PR의 머지 기준이 흔들린다.

- 같은 합성 규모(1000명×24개월)를 99882fb(#86 이전)와 main에서 반복 측정했다. 로컬 대시보드는
  1.6~2.3초 대 1.7~2.0초로 회귀가 아니었다. CI 실행 환경이 로컬보다 약 1.5~2배 느려 한도에 붙어 있었다.
- 원인은 대시보드 한 요청이 정정판 기준 관측을 두 번 읽는 데 있었다. 보고서는 선택 월만, 추이는 전체 월을
  읽는데, 월 조건을 걸어도 직전 기록 계산(window)을 전체에 대해 수행해 1000행 조회도 약 0.2초였다.
  관측 행마다 당시 정보 JSON 두 개(현재·직전)를 매번 해석했고, 추이는 쓰지 않는 월별 팀 집계와 정렬을 만들었다.

예산(3초·쿼리 12회)은 WP01 기준 계약이므로 완화하지 않고 처리 비용을 줄였다.

## 변경

- 대시보드는 같은 정정판 상한으로 전체 관측을 한 번 읽어 보고서와 추이에 함께 넘긴다.
  보고서는 그중 선택 월만 고른다. 출처·정렬·월별 확정 처리 유형 연결이 같으므로 결과가 같다.
  `report()`·`trend()`의 기존 호출(Excel 내보내기 등)은 그대로 각자 읽는다.
- 한 조회 안에서 같은 당시 정보 JSON 원문은 한 번만 해석한다. 해석 결과는 `monthly_profile`이
  복사해 쓰므로 관측끼리 공유하지 않는다.
- 추이는 요약만 쓰므로 월별 정렬·팀 집계를 생략한다(`summary_only`). 요약 계산은 같은 행에서 한다.
- 잔액 계산식·집계 계약·DB 스키마·화면은 바꾸지 않았다.

## 실제 검사

운영 환경 파일·DB 없는 worktree, Python 3.13, 명시적인 임시 `DATABASE_PATH`, 합성 자료를 사용했다.

- `tests/test_dashboard_shared_events.py`: 정정판(기준·정정·최신 상한), 미관측 월, 기존 장부 비재직·복귀,
  개인번호 없는 공용계정, 보정만 있는 계정, 미관측 인원, 미분류 유형, 월간 확정 처리 유형을 섞은 합성 장부에서
  3개 정정판 × 2개 범위 × 3개 유형 × 팀 조건 2개 × 3개월의 보고서(행·요약·팀·미분류·보유 팀)와 추이가
  관측 공유 전후 같음을 확인한다. 대시보드가 관측을 한 번만 읽는지도 확인한다.
- `pointbook-ledger-review` 기준으로 화면·보고서·Excel의 같은 집계 계약, 공용·비재직·미관측 잔액 보존,
  정정판 재현을 대조했다. Excel 내보내기는 기존 경로 그대로다.
- 같은 기계에서 짝지어 측정한 대시보드 최소 시간: 1.52~2.54초 → 1.21~2.18초(약 11~26% 단축).
  규모 검사 대시보드 쿼리 11 → 9회, 1000명 1.56·1.61초.
- 전체 서버 검사 coverage 94.55%, Ruff check/format, mypy app scripts 통과.

## 한계

정정판 경로의 SQL(정정본 window와 JSON 추출)은 그대로이며 여전히 가장 큰 비용이다. CI 실행 환경의
변동으로 한도에 다시 가까워지면 SQL 개선을 별도로 검토한다. 운영 DB·환경, 버전·태그·릴리스·배포는
변경하지 않았다.
