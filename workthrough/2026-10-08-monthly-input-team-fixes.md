# 편집 JPEG·이월 검수·팀 공용계정 후속 수정

## 문제와 확정 범위

사용자가 편집한 두 사진의 형식 오류, 이월 입력과 참고 잔액의 혼동, 비재직 잔액 입력 부담,
팀 화면의 공용계정 누락을 제보했다. 논의한 계획을 구현하도록 승인했다.
비재직 전환·기존 비재직 유지 대상의 잔액 증가는 경고가 아닌 확정 오류로 요청했으며,
일반 인원 수는 유지하되 팀 전체 총 잔액에는 공용계정을 포함하기로 결정했다.

## 변경

- JPEG segment 길이·SOF/SOS·entropy escaping/restart를 따라 주 이미지 EOI를 찾는다.
  APP 안의 썸네일과 본문 뒤 부가 데이터의 종료 표시를 주 이미지 종료와 혼동하지 않는다.
  원본 크기·확장자 대조를 유지하며, 두 파일 검사 후에만 AI 호출을 시작한다.
  원표·명단·이름 재판독과 직접 Gemini 호출에 동일한 본문을 재인코딩 없이 전달한다.
- 이월은 빈칸으로 시작하고 직전 실제 총 잔액을 별도 표시한다. 인원별 복사 버튼은
  실제 0원도 입력하며 기록이 없으면 비활성화한다. 입력 값으로 미입력·완료·오류를 계산하고
  초안 재개·필터·다음 입력/오류 이동에 반영한다. 별도 완료 상태를 DB에 추가하지 않는다.
- 비재직 두 구역의 이월이 이전 총 잔액을 초과하면 브라우저와 서버의 잠금 전후 검증에서 거부한다.
  오류 입력은 초안에 남고, 이전 기록 없음과 실제 0원을 구분한다. 요청서의 재직 유지·복귀·공용계정,
  기존 장부·동일 확정 재전송의 계산은 유지한다. 일반적인 음수 순사용 계산을 전역 금지하지 않는다.
- 팀에 연결된 공용계정을 목록·상세에 표시하고 공용 수·잔액을 분리하며 전체 잔액에 합산한다.
  일반 인원 수와 공용계정 수를 명/개로 구분한다. 팀 없는 계정을 추정 배정하지 않는다.
  보고서 링크는 기존 일반·공용 전체 조회로 연결한다. 큰 정수 합계는 Python 정수 연산을 유지한다.
- DB 스키마·Excel 열 계약·의존성 lockfile은 변경하지 않는다. 검수 표의 행 높이와 데스크톱 폭,
  모바일 상세 화면을 기존 브라우저 검사 기준으로 맞췄다.

## 실제 검사

운영 환경 파일·DB 없는 worktree, Python 3.13, 명시적인 임시 `DATABASE_PATH`, Mock/합성 자료를 사용했다.

- 이월·월간·비재직·연결 서명·초안 관련 100개 검사 통과. 기준 잔액을 별도 DB 세션에서
  바꾼 뒤 확정 잠금을 얻는 경합도 거부하고 입력을 보존함을 확인했다.
- 전체 서버 초회: 945 passed / 1 failed, coverage 94.25%. 기존 비재직 증가 허용 검사가
  새 업무 규칙과 충돌했으며 증가 거부→동일 잔액 확정·집계 보존 계약으로 갱신했다.
  수정한 해당 검사와 추가 경합 검사를 위 관련 100개 검사에서 통과했다. 최종 전체 판정은 PR CI로 확인한다.
- 구버전 Chromium 전체 E2E **26 passed**. 33행 검수 높이, 데스크톱 전체 표 너비,
  모바일·집중 입력·작업 위치 복원, 잔액 복사·초안 재개·동시 오류 이동·서버 확정 거부,
  팀 공용계정과 잔액 표시를 검증했다. 합성 Compose는 별도 프로젝트로 실행 후 정리했다.
- Ruff check/format, mypy app scripts 통과. 기반 히스토리 검사는 v1.6.0 CI 증거를 사용하고,
  새 커밋 패치는 Gitleaks로 검사했다.
- JPEG 합성 baseline/progressive fixture를 별도 임시 디코더로 해독 확인했다.
  제공된 두 실제 사진은 로컬 메모리에서만 검사해 사진 본문이 원본의 정확한 prefix임을 확인했다.
  실제 파일·번호·경로는 저장소·CI·외부 AI에 넣지 않았다.
- 이월과 JPEG를 각각 독립 검토했다. 다음 오류 이동과 독립 E2E fixture 문제를 수정했고,
  최종 정적 검토에서 추가 차단 결함은 발견하지 못했다.

## 한계

실제 Gemini API 인식과 Win7 Chrome 109·갤럭시 전체 실기 수용은 미실행이다.
