# 사진 이름 오인식 재확인

## 문제와 범위

사진에서 비슷한 받침 또는 받침 유무를 잘못 읽으면 서로 다른 이름으로 들어갈 수 있다.
특정 실명 교정표를 두지 않고 Gemini의 독립 이름 재판독과 원본 대조 안내를 추가한다.
기존 업무 식별자는 8자리 포인트번호이며, 이름/개인번호 중복을 허용하는 계약을 유지한다.
자료 월·처리 월, 금액·이월·비재직 전환 규칙을 변경하지 않는다.

시작 source는 main `96ad517`. 관련 기준은 #48 R01/R03/R05/R06/R13/R20/R26,
S02/S08/S09/S11 및 WP02 #50·WP05 #53·WP08 #56의 후속 개선이다.

## 변경

- 원표의 첫 인식 후 원사진으로 이름을 독립 재판독한다. 첫 인식 이름이나 DB 인원 목록을
  추가 요청에 보내지 않는다. 같은 Gemini 제공자와 설정 모델을 사용한다.
- 행 순서만으로 대응하지 않는다. 포인트번호 또는 팀·계급·개인번호/금액으로 묶어 이름을
  비교하고, 중복/행 누락/근거 불일치는 사람이 확인하도록 남긴다. 이름·번호·금액·비고를 자동 교체하지 않는다.
- 한글 한 음절의 종성만 다른 이름은 같은 팀·정규화 계급 안에서 명단 후보로 보여준다.
  후보가 하나여도 개인번호 자동 보완이나 유사 이름으로 DB 자동 연결을 하지 않는다.
- 첫 인식/재판독의 차이와 후보를 이름칸 아래 표시하고 초안에 보존한다. 재검수 후에도 경고를
  남기며 기존 최종 경고 확인을 요구한다. 이름 변경 시 기존 계정 연결·이월 재입력 계약을 따른다.
- 대응하지 못한 재판독 원문은 행과 분리해 문서 대조 안내에 저장한다. 독립 검토에서 찾은
  근거 유실과 명단에서만 발생한 이름 차이의 표시 누락을 보완했다. 이전 초안의 안내 형식도 읽는다.
- 두 장은 두 원표를 먼저 확보한 뒤 이름을 재확인한다. 사진별 기존 시간 예산 안에서만 진행하고
  실패/시간 초과/실행 슬롯 부족이면 원표를 보존해 직접 확인을 안내한다. 작업이 실제 끝나기 전에는
  실행 슬롯을 반환하지 않는다. 같은 모델의 두 응답 일치를 정확성 보장으로 표현하지 않는다.
- 사용 안내에 사진마다 추가 AI 요청이 발생할 수 있다는 점과 사용자 확인 절차를 명시했다.

## 검증과 한계

운영 `.env` 없는 WSL 격리 worktree, Python 3.13.15, uv.lock, 합성 자료와 임시 DATABASE_PATH를 사용한다.

- 초기 관련 AI/두 사진/이름 검증 125건 통과. 행 순서 변경·동일 금액 반복·누락·중복·받침/모음 차이,
  불일치 초안 재개, 원값 보존, 이름 수정 후 정확한 기존 계정 연결을 포함한다.
- 추가로 두 원표 확보 후 재확인 timeout/busy 시 원표 보존, 시간 예산 소진, 복수 후보,
  경고 제거 시 토큰 재검수, 대응 불명 원문 보존, 명단 전용 이름 차이 표시를 검증한다.
- 전체 pytest **870건 / coverage 94.24%** 통과. 구버전 Chromium **24 E2E** 통과
  (이름칸 경고 표시·행 삭제·초안 재개·390px 화면 포함).
- Ruff check/format, mypy app scripts, 임시 Alembic upgrade/check, pip-audit,
  변경 소스 사본 gitleaks, 격리 production Compose 기동·백업·복원·재시작 smoke 통과.
  마지막 공통 안내 문구 수정은 최종 PR CI에서 함께 검증한다.
- 실사진 외부 전송·운영 DB 읽기/쓰기·배포·릴리스는 수행하지 않는다. 실제 Gemini 정확도/추가 지연,
  Win7 Chrome109·갤럭시 실기는 미검증이다. 모의 응답 테스트 통과를 실제 인식 정확도로 주장하지 않는다.
