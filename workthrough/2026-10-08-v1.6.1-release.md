# v1.6.1 버전 표시·릴리스·운영 반영

## 문제와 범위

PR #81의 편집 JPEG·이월 입력/검수·팀 공용계정 수정은 운영에 반영했지만 앱 버전은 v1.6.0이었다.
사용자가 v1.6.1 갱신을 요청했다. 버전 상수·기존 버전 검사·README·CHANGELOG·아키텍처 안내를
갱신하고, 검증한 소스의 태그·릴리스와 운영 이미지에 같은 버전을 연결한다.

R24/R25/R26 → #48 및 WP10 #58 후속 릴리스 → 기능 [PR #81](https://github.com/jihoon22-lee/PointBook/pull/81)
→ source `1b1febf3ef7ed88d04fde796e5968c960ef75a05` → 본 릴리스 PR의 source·merge ref CI.
기능 [CI](https://github.com/jihoon22-lee/PointBook/actions/runs/37738200283)는 947 tests / coverage 94.25%,
26 E2E·운영 모드 Compose smoke·필수 7개와 Quality gate를 통과했다.

## 변경과 검증

기능 로직·DB 스키마·의존성 lockfile은 변경하지 않는다. 운영 환경 파일 없는 worktree와 임시 DB에서
기존 버전 표시 3 tests, Ruff check/format, mypy app scripts와 릴리스 노트 추출을 통과했다.
독립 검토에서 버전·문서·릴리스 절 및 동적 버전의 lockfile 계약을 확인했다.
새 변경 민감정보 검사와 PR 필수 CI 전체 통과 후 squash merge하고 머지 소스에 v1.6.1 태그를 발행한다.

운영 반영은 검증 source와 이미지 ID를 고정해 이전 이미지 보존 → DB 이전 예행 → 정지 후 백업 →
기동·재시작·장부 대사 순서로 수행한다. 환경 설정·마운트·포트를 유지하며 기존 장부 행 내용도
대조한다. 실제 월간 입력·확정을 검증 목적으로 수행하지 않는다.

최종 source·CI·이미지 및 운영 확인 결과는 릴리스 노트에 연결한다.
실제 Gemini API·Win7 Chrome 109·갤럭시 전체 실기 검증은 미실행이며 합성 자동 검증과 구분한다.
