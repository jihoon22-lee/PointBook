# 지급표·개인번호 명단 두 사진으로 월간 초안 만들기

## 문제와 결정

기존 이미지 경로는 파일 한 장만 받았다. 금액표와 개인번호 명단이 나뉜 요청서는 인원 식별과
금액을 결합할 수 없었고, 번호 없는 AI 행은 확정용 포인트번호 검증 때문에 자동 연결 전에
원문 오류가 되었다. 사용자 업무에서 자료 월과 처리 월은 다르다. 전월 지급표로 이번 달
충전을 처리하므로 사진 제목에서 처리 월을 덮어쓰지 않는다.

금액표를 인원·순서·팀·계급·충전액의 기준으로 유지한다. AI가 각 사진을 개별 구조화하고
서버가 팀·계급·이름의 양쪽 유일 일치를 검사하여 명단의 4자리 개인번호만 보완한다.
계급 약칭을 대응하고 선행 0을 유지한다. 팀/계급 차이·중복·번호 충돌·누락은 자동 결합하지
않으며 원문과 경고를 보존한다. 명단만 있는 사람은 0원 충전 행으로 만들지 않는다.

사진 결합 후 기존 이름·개인번호·계정 유형 기준으로 등록 계정을 연결한다. 8자리 포인트번호는
생성하지 않는다. 기존 프로필 차이 선택·이월 재입력·전체 DB 대조·장부 확정 계약을 재사용한다.
포인트번호 미발급/이월 미입력 상태도 초안으로 남긴다. 기존 한 장·Excel v1/v2·붙여넣기는 유지한다.

## 변경과 추적

- AI: 별도 명단 prompt/스키마 검사, 공유 실행 슬롯·시간/크기 한도·오류 비식별화 유지.
  포인트번호 미기재만 정상 연결 대상으로 분리하며 금액·자료형 오류는 계속 보존한다.
- 업로드: 사진 역할별 필드 두 개, 파일별 검사 후 외부 전송. 중복 파일 필드·초과 파일·
  XLSX/명단 또는 붙여넣기/사진 혼합 입력을 차단하고 모든 업로드 파일을 닫는다.
- 검수/초안: 행별 대조 경고와 문서 단위 미사용 명단 안내·원문을 저장한다. 독립 검토에서
  첫 지급행 삭제 시 미사용 명단 안내도 사라지는 문제를 발견해 문서 단위로 분리했다.
  안내가 바뀌면 검수 토큰을 다시 확인하며, 빈 신규 필드는 이전 재전송 해시에 추가하지 않는다.
  미연결 행이 있어도 입력 인원 수와 유효한 금액 합계를 표시한다. 오류 금액은 0원으로 합산하지 않는다.
- 보안 검사에서 기존 lockfile의 urllib3 2.7.0/Werkzeug 3.1.8 취약점 4건이 나왔다.
  안내된 수정 버전 2.8.0/3.1.9로만 갱신했다. 앱 제공자·키·운영 설정·DB 스키마 변경은 없다.
- 기준: #48 R01/R03/R05/R06/R07/R13/R20/R22/R26, S02/S08/S09/S10/S11;
  기존 WP02 #50·WP05 #53·WP08 #56·WP09 #57 계약의 후속 개선이다.
  시작 source는 main `e650012`. 이 PR의 source/merge SHA와 CI가 최종 증거다.
  [PR #78](https://github.com/jihoon22-lee/PointBook/pull/78), 최초 구현 source `15d1a97`.
- 기울어진 지급표의 팀 경계에서 인접 행을 잘못 분류한 수동 판독을 사용자 피드백으로 정정했다.
  화면의 수평 높이 대신 행 선을 따라 팀 병합 셀을 확인하도록 prompt를 보완했다.
  이 안내만으로 실제 OCR 정확도가 검증되었다고 주장하지 않는다.

## 실제 검증

운영 환경 파일 없는 WSL 격리 worktree, Python 3.13.15, uv.lock, 명시적 임시 DATABASE_PATH와
합성 자료를 사용했다. 실사진은 별도 비공개 입력 표 작성에만 사용했고 Git/CI/외부 AI로 보내지 않았다.

- 관련 AI·연결·초안 HTTP 회귀 114건 통과. 일반 multipart CSRF 두 파일 요청 포함.
- 전체 pytest/coverage는 보안 의존성 갱신 전후 모두 831건 통과, coverage 94.17%.
  이후 미연결 입력 합계 표시를 추가했으며 관련 HTTP 회귀와 최종 PR CI에서 검증한다.
- Ruff check/format, mypy app scripts, 임시 Alembic upgrade/check 통과.
- 구버전 Chromium E2E: 첫 실행 23건 통과/신규 검사 1건 실패(제목 행까지 센 테스트 선택자).
  tbody로 바로잡은 최종 24건 통과. 두 장 업로드→첫 행 삭제→재검수→초안 재개 및 390px 화면 포함.
- 격리 production Compose smoke 통과: 임시 환경/DB에서 기동·백업·복원·재시작 검증.
- 패치 후 pip-audit 알려진 취약점 없음. 저장소 자체 패키지는 PyPI 조회 대상에서 제외됨.
- gitleaks: 기존 61커밋과 Git 대상 소스 사본(미커밋 파일 포함)에서 유출 없음.
- 실제 Gemini 두 장 인식 성공률과 Win7/갤럭시 실기는 미검증이다. 자동 Chromium 결과로 대체하지 않는다.
- PR CI 첫 최종 실행은 835건 통과/1건 실패(1,000명 검수 3.017초, 기준 3초), coverage 94.18%였다.
  합계 표시가 정상 행의 금액을 다시 파싱하지 않게 하고 빈 행별 경고 필드의 HTML을 생략했다.
  성능/쿼리 수 기준을 완화하지 않고 관련 규모 회귀와 CI를 다시 확인한다.
  수정 후 커버리지 계측을 포함한 규모/두 사진 회귀 27건 통과. 합성 1,000명×24개월은
  검수 39쿼리/2.456초, 초안 저장 14/0.874초, 대시보드 10/2.611초, Excel 6/1.268초였다.
