# 기존 장부·인원 정보·조회 양식 복구

v1.4.0 실기 확인에서 기존 Excel 지급 이력을 미확인으로 표시하고, 월별 인원 프로필·정정판을
일반 조회 표에 노출한 회귀가 드러났다. 대시보드의 재직·비재직 전환 인원도 단순 기록 건수로
바뀌어 있었다. 사용자 업무 기준에 따라 이 동작을 바로잡는다.

- 기존 Excel 일반 인원: 월별 충전액 0원은 비재직, 지급액 있음은 재직. 공용계정은 항상 active.
  원본 금액/기존 불변 revision JSON을 다시 쓰지 않고 선택한 기록의 지급액으로 상태를 읽는다.
  신규 Excel 이관도 같은 규칙으로 상태를 보존한다. 웹의 명시적 상태 기록은 유지한다.
- 이름·포인트번호·개인번호·팀·계급은 현재 인원 마스터로 조회·팀 필터·집계·Excel을 통일한다.
  월별 별도 인원 프로필 수정은 제거한다. 기존 감사 원본은 보존한다.
- 개인 월별표는 월/이월/당월 충전/순사용/총잔액의 5열이다. 월 링크로 금액을 수정한다.
  반복 인원 정보·당시·출처·정정판 열과 현재 정보 버전을 제거했다.
- 대시보드에 월별 재직·비재직 전환 수를 복구했다. 직전 실제 월간 기록과 비교하며 기존
  비재직·미관측 달·잔액 보정·공용계정을 신규 비재직 전환으로 세지 않는다. Excel 요약도 일치한다.
- 월 선택 목록을 복구하고 일반 보고서에서 정정판 입력·행별 내부 버전을 뺐다. 변경 전후
  금액 비교는 변경 이력 링크에서 열 수 있다.

관련 명세: #47/#48/#58의 사용자 정정, R01/R14/R16/R18/R21/R23 및 S04/S05/S10/S11.
사용자가 과거 팀·계급·월별 별도 인원 정보 관리를 명시적으로 제외한 결과를 AGENTS와 문서에 반영했다.

## 실제 검증

- 환경 파일 없는 `/tmp` worktree와 임시 DATABASE_PATH, Python 3.13.
- `uv run ruff check .`, `ruff format --check .`, `mypy app scripts` 통과.
- 전체 `pytest --cov=app --cov-report=term-missing --cov-fail-under=85`: **706 passed / 93.62%**.
- `test_legacy_status`: 기존 migration 형태의 원본 revision으로 재직/비재직/복귀/공백,
  금액 정정 전후 cutoff, 공용 제외, 현재 인원 정보/팀 필터, HTML/Excel 집계를 검증했다.
  현재 마스터 상태에 따라 과거 상태가 바뀌지 않으며 원본 금액·감사 JSON도 유지된다.
- 구버전 Chromium 로컬 E2E: **15 passed**. 개인 표의 5열과 390px 가로 넘침을 검증했다.
  최초 실행에서는 초안 저장 후 비동기로 시작하는 재검수 이동을 기다리지 않아 다음 입력이
  이전 화면에 들어가는 테스트 타이밍 문제가 발생했다. 재검수 클릭에 명시적 navigation 대기를
  추가했으며 최종 커밋은 PR CI에서 다시 검증한다.
- 승인된 비공개 실제 데이터 사본을 읽기 전용으로 열어 모든 월의 재직/전환 수와 현재 인원
  정보·팀·계급을 대사했다. 모두 일치했고 원본 장부/감사 데이터에 쓰지 않았다.

PR CI·정확한 후보 이미지와 갤럭시/Win7 수용·운영 배포 결과는 #58에 연결한다.
이 기록은 운영 배포나 전체 실기 검증을 완료했다는 뜻이 아니다.
