# 경고 스타일·한국 시간·정합성 이름 표시·반영 배너·월간 요약·접근성 개선

## 문제와 확정 범위

v1.6.1 전체 코드 리뷰(2026-10-18)의 디자인·사용성 항목이다. 계획의 PR-D 범위(B10, U1~U12)다.
선택형 기능(팀 이름 변경·홈 업무 현황·세션 유효시간 설정)은 포함하지 않는다.

- B10/U1: `.alert-warning`이 정의되지 않아 확정 전 경고·연결 확인·모의 AI·미확인 잔액·정합성 이슈·
  인스턴스 공지가 일반 글처럼 보였다. 식별자 변경 경고는 수식어 없는 `.alert`였다.
- U2: 초안 목록은 UTC 원문(마이크로초 포함), 설정의 복구 검증 시각은 ISO 문자열로 보였다.
- U3: 개인 상세·대시보드의 여러 줄 비고가 한 줄로 합쳐지고, 검수의 가져온 원문도 줄바꿈이 사라졌다.
- U4: 정합성 이슈와 복구 전후가 `인원 12`, `기록 345` 같은 내부 ID를 보였다.
- U5: 변경 이력 목록에서 예전 작업을 열어도 "검토한 변경을 반영했습니다"가 보였다.
- U6: 월간 확정 상세가 `N명 반영`만 보였다.
- U7: 처리 이력의 월에서 그 달 보고서로 이동할 수 없었고 총 잔액의 집계 기준 설명이 없었다.
- U8: 대시보드의 팀을 자유 입력으로 받아 오타 시 빈 결과가 나왔다.
- U9: 로그인 입력에 자동완성 용도가 없었다.
- U10: 정적 파일 URL에 버전이 없어 업그레이드 뒤 이전 JS·CSS가 남을 수 있었다.
- U11: 640px 이하에서 상단 메뉴가 여러 줄로 감싸져 고정 헤더가 커졌다.
- U12: 추가한 검수 행의 접근성 이름이 영어 키였다. 빈 요청서 시작이 다른 버튼 문구를 바꿨다.
  대시보드 열 정렬을 키보드로 쓸 수 없었다. 비밀번호 변경 오류 화면에서 운영 상태 카드가 사라졌다.
- E2E 작성 중 확인한 기존 결함
  - 두 사진 업로드(#78, v1.6.0) 뒤 "빈 요청서 시작"이 빈 사진칸 두 개를 보내 `/monthly/start`의
    파일 1개 한도에 걸렸다. 화면 대신 JSON 400(`Too many files`)이 보였다.
  - 정렬 제목의 화면낭독용 문구(절대 위치)가 표 가로 스크롤에 갇히지 않아 375px에서 인원 목록 페이지
    전체가 가로로 밀렸다.

## 변경

- 호박색 `.alert-warning`, `.note-text`(pre-line), 가져온 원문 pre-wrap을 추가했다. 640px 이하 메뉴는
  한 줄 가로 스크롤로 바꿨다.
- `kst_datetime`이 기록된 ISO 문자열도 한국 시간으로 바꾼다. 해석할 수 없는 값은 원문을 그대로 보인다.
- 정합성 이슈와 복구 전후는 `이름(0000 0101)`을 보인다. 서명된 복구 계획의 내용은 바꾸지 않고
  화면에서만 현재 인원 정보로 표시한다.
- 반영 직후 리다이렉트에만 `?done=1`을 붙여 성공 배너를 보인다. 저장된 결과 주소와 재전송 동작은
  그대로 둔다. 목록에서 연 화면의 제목은 "변경 이력 상세"다.
- 월간 확정 상세에 신규·복귀·재직 유지·비재직 전환·기존 비재직 잔액 보존별 인원을 펼침 목록으로
  추가했다. 이름은 다른 보고서처럼 현재 인원 정보로 보인다. 기존 `N명 반영` 줄은 그대로 둔다.
- 처리 이력의 월을 대시보드 링크로 바꾸고 총 잔액 기준(그 달 실제 확인 잔액, 공용·비재직 보존 포함)을
  설명했다. 집계 값은 바꾸지 않았다.
- 대시보드 팀 조건을 팀 마스터 선택 목록으로 바꿨다. 매개변수 `team_name`은 유지하며 지운 팀 이름으로
  연 주소도 선택 상태를 유지한다.
- 로그인 autocomplete, 모든 정적 JS·CSS의 `?v=버전`을 추가했다.
- 추가 행 입력칸은 `N행 이름`처럼 기존 행과 같은 형식의 라벨을 쓰고 행 삭제 뒤 번호를 다시 매긴다.
  업로드 화면은 실제로 누른 버튼(`event.submitter`)만 진행 문구로 바꾼다. 대시보드 정렬 제목은
  버튼으로 감싸 Enter·Space로 정렬하고 `aria-sort`를 알린다. 비밀번호 변경 오류에도 운영 상태를 보인다.
- `/monthly/start`는 업로드와 같은 파일 2개·본문 한도를 쓰고, 선택된 사진은 읽지 않고 닫는다.
  브라우저 폼은 보안 토큰을 폼 필드로 보내 토큰 검사가 먼저 폼을 읽으므로, 토큰 검사·라우터·요청 한도가
  같은 업로드 폼 경로 상수를 쓴다.
  `.table-wrap`에 기준 위치를 주어 화면낭독용 문구를 표 스크롤 안에 둔다. 한 줄 메뉴에서 로그아웃
  버튼이 줄어들며 글자마다 줄바꿈되던 문제(헤더 140px)도 막았다(92px).
- `docs/usage-guide.md`를 갱신했다. DB 스키마·잔액 계산·Excel 계약은 바꾸지 않았다.

## 실제 검사

운영 환경 파일·DB 없는 worktree, Python 3.13, 명시적인 임시 `DATABASE_PATH`, Mock/합성 자료를 사용했다.

- `tests/test_ui_usability.py` 12개를 먼저 작성해 앱 변경을 되돌린 상태에서 모두 실패하고,
  변경 후 모두 통과함을 확인했다. 빈 요청서 시작 검사는 브라우저처럼 보안 토큰을 폼 필드로,
  `filename=""` 파트를 직접 보내 main에서 JSON 400을 재현한다. 처음에는 헤더 토큰으로 보내 토큰 검사의
  폼 파싱을 놓쳤고, 독립 검토가 이를 지적해 고쳤다(토큰 검사 한도만 되돌리면 실패함을 확인).
- 독립 정적 검토의 낮은 확신 지적도 반영했다. 행 삭제 뒤 서버가 그린 행의 라벨 번호도 다시 매기고,
  정렬 버튼이 제목 칸 전체를 채우며, 월간 요약은 확정 당시 포인트번호 기준임을 명시한다.
- 처리 이력 월을 읽는 기존 검사 3곳의 정규식이 월 링크를 허용하도록 고쳤다. 과거 팀 이름이 보고서에
  나오지 않는지 보는 검사는 팀 선택 목록(팀 마스터 전체)을 제외한 보고서 영역만 보도록 좁혔다.
- 전체 서버 검사 coverage 94.36%. 규모 검사는 단독 실행으로 통과했다.
- Ruff check/format, mypy app scripts 통과.
- 구버전 Chromium E2E에 키보드 정렬·추가 행 라벨·빈 요청서 버튼·375px 메뉴 한 줄·인원 목록 가로 넘침
  검사를 추가했다. 첫 실행에서 빈 요청서 시작 실패와 375px 넘침 2건이 드러나 위 결함을 고쳤다.
  임시 DB 로컬 서버에서 375px 6개 화면의 문서 폭·헤더 높이를 확인했다. 수정 후 전체 E2E **31 passed**
  (기존 28 + 신규 3, 별도 Compose 프로젝트 `pb-ui` 실행 후 정리).

## 한계

별도로 검토한다. 운영 DB·환경·컨테이너, 버전·태그·릴리스·배포는 변경하지 않았다.
