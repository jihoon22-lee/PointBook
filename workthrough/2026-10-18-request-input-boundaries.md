## 변경

- 빈 계정 구분(빈 문자열·`None`·공백)은 AI·제목 있는 붙여넣기·Excel에서 일반 인원으로 읽는다.
  잘못된 값은 지금처럼 원문 오류로 남는다. Gemini 지침을 "명시된 공용만 shared"로 바꿨다.
  공용계정 신규 행에 개인번호가 없으면 기존 검증이 유형 선택을 요구한다.
- 붙여넣기는 레코드 첫 줄로 구분자를 고르고, CSV가 따옴표 안에서만 다음 줄을 이어 읽게 한다.
  닫히지 않은 따옴표나 20,000자·100줄 초과 레코드는 기존처럼 그 줄만 원문 오류 후보로 남기고 다음 줄부터 읽는다.
  원문의 CRLF는 LF로 통일한다. 탭·쉼표가 섞인 입력과 셀 안 따옴표의 기존 동작은 유지한다.
- 공용계정 보완과 검수 화면 조회는 `normalize_point_no`를 쓴다. 보완은 일반으로 읽힌 행만 바꾼다.
- 기존 Excel 이관은 정확한 제목을 먼저 배정하고 한 열을 두 항목에 쓰지 않는다. 금액 열을 필수로 하고,
  금액·잔액을 월간 입력과 같은 규칙으로 행 번호와 함께 검증하며 파일 안 포인트번호 중복을 거부한다.
  전체를 검증한 뒤 만든 인원 객체로 기록을 만들어 세션 설정과 무관하게 모두 이관한다.
- 누적 장부 이관은 월간 자동 생성과 같은 순서로 미사용 팀 색상을 배정한다.
- DB 스키마·잔액 계산식·Excel 입력 열 계약은 변경하지 않는다. `docs/excel-workflow.md`,
  `docs/usage-guide.md`를 갱신했다.

## 실제 검사

운영 환경 파일·DB 없는 worktree, Python 3.13, 명시적인 임시 `DATABASE_PATH`, Mock/합성 자료를 사용했다.

- 재현 검사(`tests/test_input_boundaries.py`)를 먼저 작성했다. 결함 재현 검사는 main에서 모두 실패했고,
  기존 동작을 고정하는 검사(잘못된 유형 오류·혼합 구분자·닫히지 않은 따옴표·정수 셀)는 main에서도 통과했다.
  수정 후 전부 통과했다. 이관 검사는 실제 CLI와 같은 `SessionLocal()`로 실행한다.
- 기존 붙여넣기·연결·자동 연결·두 사진·Excel·Gemini·이관 검사 통과.
- 전체 서버 검사 coverage 94.36%. 전체 동시 실행에서 `test_workflow_scale[1000]`의 3초 한도가
  한 번 초과했으나 단독 실행은 통과했고 쿼리 수가 main과 같았다(검수 39·저장 14·대시보드 10·내보내기 6).
- Ruff check/format, mypy app scripts, Alembic upgrade/check 통과.
- 구버전 Chromium 전체 E2E **28 passed**(별도 Compose 프로젝트 `pb-input-bounds` 실행 후 정리).
- 커밋 보안 검토가 레코드마다 남은 줄 목록을 복사하는 이차 시간 경로와 따옴표 재시도 비용을 지적했다.
  색인 순회로 바꾸고, 빈 줄은 바로 건너뛰며 따옴표 없는 줄은 한 줄로 읽는다. 레코드는 20,000자·100줄을
  넘으면 첫 줄만 원문 오류 후보로 남기며, 이 줄은 행이 되므로 기존 2,000행 한도에서 멈춘다.
  합성 최악 입력(8MB 따옴표·빈 줄 반복, 20MB 빈 줄)이 0.71초·1.7초로 입력 크기에 비례함을 확인했다.

## 한계

개인번호가 있는 신규 공용계정을 빈 계정 구분으로 입력하면 일반으로 읽힌다(제목 없는 붙여넣기와 같은
기존 절충). Excel v2에서 기존 공용계정 행의 계정 구분을 비우면 일반으로 읽혀 기존처럼 유형 불일치 오류로
안내된다. 실제 Gemini 인식과 Win7 Chrome 109·갤럭시 실기 수용은 미실행이다.
운영 DB·환경·컨테이너, 버전·태그·릴리스·배포는 변경하지 않았다.
