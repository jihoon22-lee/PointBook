# v1.4.0 B04 · 서버 초안·Excel·통합 수용

WP08 #56, WP09 #57, WP10 #58 / R05–R07, R11, R13–R18, R20–R26, S01–S12 통합.

월간 검수는 인증된 서버 초안과 canonical GET 주소를 갖는다. 원문·행 ID·출처·잔액을
저장하며 순차 debounce, 한글 조합 종료, 버전/소유권/만료 확인으로 두 기기의 덮어쓰기를
막는다. 저장/로그인 실패 시 DOM을 유지하고 새 탭 재로그인 후 CSRF를 갱신한다.
원장 확정과 초안 confirmed 전환은 한 트랜잭션이다. 초안 정리 worker는 종료 전에 끝나므로
DB 엔진 해제와 경합하지 않는다. 기본 30일·20개, JSON 16MB·원문 셀 20,000자다.

잔액 집중 보기·최근 검수 변경 필터·정렬·미입력 이동·Enter 연속 입력을 제공한다. 표시용
필터 변경이 검수 승인을 해제하던 브라우저 결함을 수정했다. 숨긴 행도 저장/확정 대상에
포함한다. 운영 화면은 실제 버전·경로·최근 백업/예행 검증/복원과 미실행을 구분한다.

최종 통합 검토에서 월간 신규 팀의 색상 자동 배정과 XLSX의 명시적 계정 유형 보존을
확인하고 회귀 테스트를 추가했다.

표준 v1 `.xlsx`는 RawRequestRow→검수·초안으로 연결한다. ZIP/XML 크기·중복·행/셀 위치·
수식·매크로·외부 관계를 검사한다. defusedxml을 운영 의존성으로 고정하고 입력/출력의
실행 슬롯을 2개로 제한한다. Report의 범위·정정판·정렬을 그대로 XLSX로 쓰며 모든 불신
텍스트는 문자열 셀로 보존한다. 없는 관측/활동은 0원으로 만들지 않는다.

앱 버전은 1.4.0으로 준비했으며 changelog는 릴리스 후보로 구분한다. IE11은 기능 폼 대신
안내를 표시한다. Chrome109/TLS 설명은 Google/Chromium 공식 근거와 실제 CLI에 맞췄다.
실제 설정 모델의 최신 API 지침에 따라 Gemini sampling parameter를 제거했다.

검증(운영 env 없는 WSL worktree, Python 3.13, 합성 SQLite·파일):

- 전체 pytest **697개 통과, coverage 93.26%**. 이후 Gemini parameter 수정의 관련 회귀 통과;
  최종 소스 전체 검증은 PR CI로 연결한다. Ruff·format·mypy 통과.
- 초안·Excel·운영 상태 테스트: 소유권/CSRF/세션 폐기·재로그인·두 탭·만료/삭제/
  저장 실패·확정 원자성, 실제 XLSX 왕복과 ZIP/XML/엔티티/수식/매크로/외부 링크,
  정정판·범위·출력 정밀도·슬롯 취소 경계 검증.
- 구형 Chromium Compose E2E **15개 통과(26.67초)**: autosave/새로고침/별도 context,
  두 탭 충돌·fork, 실패·재로그인, 한글 조합 이벤트·390px 집중 입력, 숨긴 행 확정,
  표준 파일→초안→확정→개인 보고서 다운로드와 IE User-Agent 안내 포함.
- `tests/test_workflow_scale.py`: 200/1,000명×24개월 검수/저장/대시보드/출력 SELECT
  **36/13/7/4개**. 1,000명 응답 **0.737/0.302/0.728/0.315초**, 3초 검수 예산 유지.
- `bash e2e/production-smoke.sh`: e14, custom env/mount, 검증 백업→복원→기동·재시작
  영속성 PASS. 운영 자료는 이 자동 검사에 사용하지 않았다.
- ResourceWarning 없음. Starlette httpx2 전환 안내 1건은 남아 있으며 경고를 숨기지 않았다.

실제 Gemini는 기존 키·모델 `gemini-3.6-flash`에 합성 사진만 보냈다. 모델 목록 조회는
성공했지만 인식 3회는 `503 UNAVAILABLE` 과부하였다. 성공 인식으로 기록하지 않으며
다른 모델/제공자로 자동 변경하지 않았다. Win7/Android 실제 장치도 미실행이다.
운영 사본·후보 이미지·배포의 실행 증거는 #58에 추가하고 필수 수용 전 최종 태그/릴리스와
마일스톤을 완료 처리하지 않는다. [요구사항·시나리오 수용 표](../docs/v1.4.0-acceptance.md)에
모든 R/S의 구현·테스트·남은 환경 경계를 연결했다.


WP10의 운영 사본 수용 준비에서 검증용 장부를 실제 운영으로 오인하지 않도록 선택적인
`INSTANCE_NOTICE`를 모든 HTML 화면에 표시한다. 기본 운영은 빈 값이며 검증 후보는
저장 대상이 별도 사본임을 안내한다. 기존 template/version·운영 상태·초안 회귀와 타입/린트를
확인하며 최종 CI는 해당 후속 PR에 연결한다. 실제 운영 장부의 사본은 원래 열의 모든 행,
금액·현재값·FK·무결성·미확인 역사 baseline을 보존했다. 남아 있던 기본 암호 계정은 기존
서비스의 암호 변경 경로로 강화했고, 현재 설정 계정의 암호는 유지했다. 최종 실기/운영 전환
상태는 #58의 실행 기록을 따른다.
