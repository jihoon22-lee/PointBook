사용자가 발견된 이슈 전체 수정, v1.5.1 릴리스 후 운영 배포까지 승인했다.

## 문제와 변경

- P1: 기존 비재직 A의 번호를 다른 인원 B에게 재사용한 뒤 초안을 열면 A의 잔액을 B에게
  적용할 수 있었다. 비재직 이월에 입력 당시 인원 ID·번호·이름·개인번호·유형·월·처리 구분을
  서명해 연결하고, 첫 검증과 writer lock 내 재검증에서 현재 대상과 일치할 때만 적용한다.
  구버전 초안·불일치·위변조·제외 입력은 원문 보존 목록으로 분리하고 현재 대상에 재입력받는다.
  기존 초안 map과 원문을 유지하며 보존값을 묵시적으로 적용하거나 다시 부활시키지 않는다.
- 재직 기간: 월간 작업을 최초 BalanceRevision의 작업/인원 ID로 연결해 번호 재사용과
  과거 삽입·후속 정정이 다른 사람의 기간을 바꾸지 않게 했다. 최신 상태 불일치는 최근 기간만
  미확인으로 표시하고 종료가 확인된 과거 기간은 남긴다.
- 팀 재직 통계: 월간 활동·잔액 각각의 당시 상태를 적용해 일반/공용/전체 필터별 금액이
  일치하게 했다. 유형 미확인 계정에도 현재 팀 필터를 적용하고 Excel과 같은 기준을 쓴다.
- FieldError와 error_fields로 오류 문구와 입력 대상을 분리했다. 잘못된 이월 `12.5`를
  눌렀을 때 이름 칸으로 이동하던 문제를 고치고 필터·집중 보기의 숨김도 해제한다.
- 변경 이력 목록·상세의 시각을 공통 KST 표시로 통일하고 전후 금액에 쉼표를 적용했다.
  UTC 저장 시각과 식별자·비고 원문은 수정하지 않는다.
- 자동 저장은 주소가 실제로 바뀔 때만 history.replaceState를 호출한다. 기존 v1.5.0 이미지에서
  URL이 같은데도 자동 저장 1회당 navigation 이벤트 1회가 발생함을 재현했다. E2E는 실제
  재검수 후 초안 페이지의 load까지 기다려 이후 Excel/자동 연결 검사의 연쇄 실패를 막는다.
- 월간·초안·CSRF 파서의 폼 상한을 64,100개로 통일했다. 요청 본문 크기 제한은 유지한다.
  앱 버전·변경 이력·사용 가이드·아키텍처를 갱신했다. DB 스키마 변경은 없다.

## 실제 검증

운영 .env·DB를 복사하지 않은 v151 worktree, Python 3.13/uv.lock, Mock과 명시적인
`/tmp/pointbook-v151-*.db`를 사용했다. 모든 재현·공개 증거는 합성 자료다.

- 전체 pytest **811건 / coverage 93.62%** 통과.
- 구형 Chromium E2E **23건 / 50.79초** 통과. 실제 오류칸 이동, 숨김 해제, 서명 없는
  이전 비재직 입력 보존·재입력·초안 복원, 자동 저장 navigation 0회, 목록/상세 KST 일치를 포함한다.
- 최초 E2E 재실행에서는 새 대기 조건을 POST 주소로 좁혀 303 이후 초안 GET을 기다리지 못했다.
  실제 최종 초안 URL의 load로 수정해 위 전체 E2E를 통과했다.
- 번호 재사용·fresh review token+옛 binding·위변조·기존 초안·인원/월/구분 변경·동시 DB 변경·
  오래된 페이지 자동 저장·중복 제출을 실제 HTTP로 재현하고 회귀 테스트로 보존했다.
- 실제 multipart 36,003필드(요청2천/비재직2천/보존2천) 처리 통과. 독립 검사에서
  body CSRF 포함 64,100필드 수용·64,101필드 거절 통과.
- 재직 기간 관련129건, 통계/보고서/Excel86건, 표시·정정·프로필51건 등 관련 검사를 통과했다.
  독립 검토에서 보존 항목의 이름/번호 혼합을 찾아 이전 서명의 번호로 통일하고 회귀 검증했다.
- Ruff check/format·mypy app scripts 통과. 임시 DB Alembic upgrade head/check 및 pip-audit 통과.
  신규 변경·커밋의 비밀정보 검사와 최종 CI·이미지 검증 결과는 PR/릴리스에 연결한다.

## 적용과 한계

9월 조회 제목과 마지막 잔액 확인 월은 별개다. 기존 비재직 인원의 이전 관측 월을 유지하며
업데이트가 새로운 9월 관측을 만들지 않는다. 이미 확정된 운영 장부를 다시 처리하지 않는다.

기존 장부·초안·이력을 보존한 채 검증 이미지로 배포한다. 사전 백업·복원 예행,
재시작·DB 대사·실제 로그인/조회·시간 표시 결과는 릴리스에 source·CI·이미지와 함께 기록한다.
실제 Win7 Chrome 109·갤럭시 실기 검증은 미실행이며 자동 Chromium 검사와 구분한다.
