# v1.7.4 — Gemini 실패 시 OpenAI 자동 전환

## 문제와 범위

v1.7.3 배포 당일 운영에서 Gemini가 한도 초과(429)를 반환해 사진 인식을 쓸 수 없었다.
같은 날 혼잡(503)도 잦았다. 제공자가 하나뿐이라 붙여넣기 외에 대안이 없었다.

- 기준 source SHA: `55a07c7b179fb163ddd87eacddcf0fb656b9d898` (v1.7.3).
- 작업 브랜치: `feature/openai-vision-fallback`.
- 요청: Gemini 키로 실패하면 OpenAI 키로 자동 인식.
- 금액 계산, 식별자, 검수·확정 계약, DB 스키마, 인식 프롬프트는 바꾸지 않는다.
- PR source SHA와 필수 CI 결과는 PR 본문에서 연결한다.

## 변경

- `app/ai/http.py`: v1.7.3의 기한·응답 제한·5xx 재시도 로직을 제공자 공통 함수로 옮겼다.
  Gemini의 동작과 오류 문구는 그대로다.
- `app/ai/openai.py`: Chat Completions와 strict JSON 스키마로 같은 프롬프트를 읽는 제공자.
  키는 Authorization 헤더로만 보내고 외부 오류 원문은 노출하지 않는다. HEIC는 호출 전에 거절한다.
- `app/ai/fallback.py`: Gemini의 서비스 실패(상태 오류·연결·응답 형식·키/모델 설정)를 OpenAI로 넘긴다.
  사진 형식·크기, 시간 초과, 동시 실행 한도는 넘기지 않는다. 남은 예산이 20초 미만이거나
  OpenAI가 읽지 못하는 형식이면 Gemini 오류를 그대로 낸다. 한 요청에서 넘어간 뒤의 호출은
  OpenAI가 맡아 실패가 확실한 Gemini를 반복 호출하지 않는다.
- `OPENAI_API_KEY`가 있을 때만 전환을 구성한다. 없으면 Gemini 단독 동작이다.
  `AI_PROVIDER`의 허용 값(mock·gemini)은 늘리지 않았다.
- 전환되면 검수 안내에 OpenAI가 인식했음을 표시하고 로그에 남긴다. 업로드·설정 화면은
  전환 설정 여부를 보여준다.
- 앱·README·버전 검사를 v1.7.4로 맞췄다.

## 한계

- 합성 표 1종, 모델별 1회 측정이다. 실제 사진(기울기·조명)에서의 정확도는 검증하지 않았다.

- 운영 `.env`에 `OPENAI_API_KEY`를 추가하고 배포해야 운영에서 동작한다.
