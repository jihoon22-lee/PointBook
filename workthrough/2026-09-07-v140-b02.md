# v1.4.0 B02 · 복구·인증·AI 경계

WP03 #51, WP04 #52, WP05 #53 / R02, R08–R13, R24–R26, S06–S08.

실행 중 SQLite 파일 복사와 불명확한 환경 경로는 검증 사본·metadata·DB 소유권 UUID,
선택 환경·canonical mount 계약으로 교체했다. 복원은 실제 migration rehearsal과 기존
DB 보존을 거치며, 배포는 immutable 이미지 ID를 고정하고 쓰기 재개 후 자동 rollback을
하지 않는다. 정기 백업 wrapper는 잠금·상태·별도 경로를 제공한다.

운영 기본값·Mock 차단, DB 관리자 암호와 초기 환경 암호의 구분, auth_version에 의한
세션 폐기, 전체 POST CSRF, 전달 IP 신뢰 범위, 요청 크기 제한을 적용했다. 알려진 무버전
구조만 과거 revision으로 판별하며 외래키·현재 schema readiness와 연결 해제를 검증한다.

AI는 제한된 thread executor에서 실행한다. timeout/취소 뒤에도 실제 worker 종료까지
슬롯을 유지한다. 파일 magic·크기·전체 JSON을 검증하고 불완전 행의 원문을 보존한다.
Gemini 키는 header로 전송하고 외부 오류는 고정 메시지·참조 ID로 제한한다. 실제 사진을
영구 저장하지 않으며 운영 오류를 Mock으로 우회하지 않는다.

검증은 운영 환경 파일 없는 worktree와 합성 DB에서 실행했다.

- `uv run pytest --cov=app --cov-report=term-missing --cov-fail-under=85`: 최종 589개 통과,
  coverage 94.34%. `ResourceWarning` 없음; Starlette의 httpx 전환 안내 1건 유지.
- `uv run ruff check .`, `uv run ruff format --check .`, `uv run mypy app scripts` 통과.
- `bash e2e/production-smoke.sh`: custom 환경·별도 mount 백업→검증 복원→기동·재시작
  영속성 PASS. 실제 운영 DB는 사용하지 않았다.
- 구버전 Chromium Compose E2E: 7개 통과. 선택 환경 파일·호스트 경로 후속 수정은
  `tests/test_config_paths.py`와 전체 pytest로 확인했으며 최종 Compose 검증은 PR CI에 연결한다.
- 백업·복원·배포 실패, WAL writer, CSRF/세션, legacy/unknown schema, AI 429/5xx/timeout/
  동시성/불완전 응답은 해당 `tests/test_*` 합성 fixture로 검증했다.

실제 Gemini API 호출과 Win7/Android 실기 검증은 아직 실행하지 않았다. 운영 정기 실행
설치·최종 migration/배포는 전체 마일스톤의 최종 배포 단계에서 수행한다.
상세 운영 계약은 [백업·복원 절차](../docs/backup-restore.md)를 따른다.
