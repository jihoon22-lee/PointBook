# v1.4.1 월간 인원·과거 월·비고 수정

## 문제와 변경

v1.4.0 검토에서 재현한 세 오류를 한 PR로 수정한다. 개별 등록·복귀 후 첫 월간
비재직 전환이 집계에서 빠졌고, 누락된 과거 월은 현재 재직 상태를 복사했으며,
Excel 여러 줄 비고는 한 줄 입력란을 거치며 붙었다.

- `observations`/`stats`: 실제 월간 확정의 전환 내역을 한 번에 읽어 처리 인원에 반영한다.
  이전 월 기록이 없어도 실제 전환을 포함한다. 기존 비재직자·공용은 전환 인원에서 제외한다.
  감사 내역은 고정된 원래 번호와 실제 확정 기록에만 연결한다. 번호 재사용 후 과거 삽입이
  다른 인원의 확정 내역을 받지 않으며 조회 기준 작업 번호를 존중한다.
- `history`: 기존 장부와 과거 삽입은 선택한 월 지급액으로 상태를 판정한다.
  일반 인원은 0원 비재직/양수 재직, 공용은 재직이다. 현재 상태·원본 정정판을 덮어쓰지 않는다.
- 검수·추가 행·금액 수정의 비고는 기존 크기의 textarea로 입력한다. CRLF/CR은 LF로
  통일하고 앞뒤 빈 줄도 보존한다. 초안·재검수·확정·보고서까지 같은 내용을 유지한다.
- 앱 버전·CHANGELOG·README·사용/Excel/구조/개발 안내와 지침을 함께 갱신한다.
  이전 릴리스·계획·검증 기록은 역사 자료로 보존한다.

관련 기준은 #48의 R01/R05/R14/R16/R18/R22/R23, S03/S04/S05/S10,
WP01/06/07/08/09다. 기존 처리 인원 의미·현재 인원 정보·개인 이력 5열을 유지한다.
사용자가 제외한 복원 시 세션 무효화 문제는 수정하지 않는다. 스키마·인증·운영 설정 변경은 없다.

## 실제 검증

운영 `.env` 없는 WSL worktree, Python 3.13, uv.lock, 명시적 임시 SQLite와 합성 자료 사용.

- `tests/test_monthly_workforce_edges.py`: 실제 등록/복귀→월간 확정→월간 이력/대시보드/팀/Excel,
  과거 월 추가·재정정→월별 상태·다음 실제 순사용·현재 상태·이전 정정판 대사 5건 통과.
- `tests/test_monthly_action_identity.py`: 실제 HTTP 번호 변경 후 누락 월 추가 회귀 1건 통과.
- 전체 pytest/coverage 실행: 712건 통과, 쿼리 수 기대값 누락 1건 실패, 커버리지 93.68%.
  실패는 상수 배치 조회 1회 추가를 반영한 뒤 해당 검사 재실행 통과. 인원·기간에 비례하는
  쿼리 증가와 응답 시간 상한 검증은 유지한다. 최종 전체 결과는 이 PR의 CI를 기준으로 한다.
- 비고 관련 HTTP 104건, 금액 수정·프로필 44건 통과(전체 검사와 중복 포함).
- Ruff check/format, mypy app scripts, 임시 DB Alembic upgrade/check 통과.
- 구버전 Chromium의 기존 E2E에 여러 줄 비고 업로드·편집·자동저장·새로고침·재검수·
  확정·Excel 대사, 금액 수정 재열기, 모바일 추가 행의 Enter 입력을 포함한다.
  첫 부분 실행은 XLSX의 2100-01 확정을 앞세워 과거 월 차단 2건이 발생했다.
  제품 변경으로 우회하지 않고 기존 시간순 테스트 순서로 전체 15건 통과(26.10초).

## 리뷰·릴리스·운영 추적

장부 독립 검토에서 발견한 번호 재사용 경계를 수정하고 실제 HTTP 회귀로 고정했다.
업무 기대값을 새 설계에 맞춰 바꾸지 않았으며 보안 기능이나 새로운 관리 화면을 추가하지 않았다.

PR의 source SHA·필수 CI 전체 결과와 v1.4.1 태그/릴리스가 최종 변경을 식별한다.
사용자가 한 PR의 머지·릴리스·배포까지 승인했다. 배포는 기존 스크립트의 사전 백업·예행 검증·
health·재시작·DB 대사를 따른다. 실제 배포 결과는 PR의 배포 기록에서 확인한다.
Win7/Android 전체 실기는 기존 합의에 따라 사용자 사후 확인이며 자동 검사 통과로 대체하지 않는다.
