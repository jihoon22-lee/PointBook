# v1.4.3 이름·개인번호 자동 연결

## 문제와 변경

v1.4.2는 번호 없는 요청서의 기존 인원을 모두 수동 연결하도록 요구했다.
사용자의 실제 업무 기준에 따라 이름·개인번호·계정 유형이 모두 일치하는 후보가
현재 DB에 한 명이면 자동 연결한다. 복수 후보·미일치만 사람이 확인한다.
개별 인원의 내부 식별은 기존 외부 발급 8자리 포인트번호를 유지한다.

- 자동 연결은 포인트번호만 보완한다. 요청서의 팀·계급·충전액·비고·원문·이월은 유지한다.
  기존 마스터를 읽어 제안하는 단계이며 인원과 장부는 확정 전 변경하지 않는다.
- 자동 상태는 원래 번호·입력 조합을 추적하며 현재 DB의 단일 일치를 재확인한다.
  식별정보·대상이 바뀌면 이전 이월을 비우고 다시 매칭한다. 공용의 빈 개인번호는
  자동 매칭하지 않는다. 같은 계정이 요청서에 중복되면 계속 차단한다.
- 명시적인 수동 선택을 유지하고, 이후 번호를 직접 다시 바꾸는 경우에도 이월을 비운다.
  신규 미발급 번호는 생성하지 않으며 기존 초안 대기 계약을 유지한다.
- 검수는 입력 복사본을 보완하고 초안은 쓰기 잠금 안에서 보완 결과를 저장한다.
  확정은 원본 제출 payload로 재전송을 먼저 확인하고 검수 fingerprint·잠금 재검증을 유지한다.
- 연결된 행의 변경 도구를 접고 예외 행만 짧게 안내한다. 2,000행의 추가 연결 상태와
  누락 인원 이월을 전송할 수 있도록 월간/초안/CSRF 폼 필드 상한을 맞춘다.
- 버전·README·CHANGELOG·업무 지침과 사용/Excel/구조 문서를 같은 PR에서 갱신한다.
  스키마와 Excel v2 열 계약은 바꾸지 않는다.

사용자 정정 계약 → #48 R03/R05/R06/R07/R17/R20/R21/R22 → WP02/08/09 →
이 PR의 source SHA·필수 CI로 연결한다. v1.4.2의 수동 연결 결정은 이번 변경으로 대체한다.
사용자가 삭제한 운영 초안은 복구하지 않으며, 배포 후 사용자가 같은 Excel로 다시 시작한다.

## 실제 검증

운영 .env 없는 `/tmp/pointbook-auto-link`, uv.lock/Python 3.13, 명시적 임시 DATABASE_PATH,
합성 자료만 사용했다. 실제 사진·이름·번호는 코드/테스트/공개 자료에 넣지 않았다.

- 자동 연결·기존 수동 연결·초안·Excel 관련 57건 통과 후 수동 반복 변경 회귀를 추가해 58건 통과.
  최종 자동 연결 13건: 33명 일괄 연결·입력 유지·확정 재전송, 정확한 두 필드 필수,
  중복 후보 선택·수동 override, 식별정보 변경/후발 중복/오입력 정정, 원문 보존,
  원본 객체 불변과 중복 충전 차단을 확인했다.
- 기존 월간·재검수·보안·인증 경계·월간 전환 126건 통과.
- 구버전 Chromium 17 E2E 통과(37.18초). 33명 전원 자동 연결, 열린 선택기 0개,
  행 높이 110px 미만, 이월 입력·초안 재개·수동 연결 클릭 없는 확정을 포함한다.
- 독립 장부 검토에서 수동 재변경 시 이전 이월 보존 경계를 보완했고 최종 추가 결함 없음.
- Ruff check/format와 mypy app scripts 통과. 최종 전체 커버리지·migrations·security·
  secret-scan·e2e·Quality gate는 PR merge ref 기준 CI 결과를 따른다.
