# v1.4.4 월간 검수 구분과 인원 정보 선택

## 문제와 변경

기존 인원 수동 연결이 요청서의 팀·개인번호 등을 현재 마스터로 덮어썼고,
행마다 연결하면 화면 맨 위로 이동했다. 사용자 확인을 거친 변경 범위로 다음을 구현한다.

- 자동 연결·직접 연결·연결 확인·신규를 태그와 행 색상으로 구분한다. 화면 열은
  이름 / 개인번호 / 포인트번호 / 팀 / 계급 / 충전액 / 이월잔액 / 비고 / 유형 순서다.
  Excel v1/v2 입력 형식은 유지한다.
- 자동·수동 연결은 포인트번호를 보완한다. 이름·개인번호·팀·계급·유형이 현재 마스터와
  다르면 현재 등록값과 이번 입력값을 함께 표시하고 항목별 명시 선택을 받는다.
  선택한 결과는 초안에 저장하며 최종 확정에서만 인원 마스터에 반영한다.
- 원래 요청값과 비교 기준·선택을 서명하여 보존한다. 기준 프로필 변경·비교 대상 변경·
  입력 수정은 다시 확인하며, 다른 인원 연결 시 이전 마스터 선택값을 새 요청값으로
  옮기지 않는다. 이름·개인번호·연결 대상 변경 시 이월 재입력 계약을 유지한다.
- 빈 팀·계급은 명시적인 이번 입력값 선택으로 지울 수 있다. 계정 유형 변경은
  기존 인원 편집 경계를 유지하며 월간 화면에서는 현재 유형을 선택한다.
- 신규 선택은 자동 연결을 건너뛰며 외부 발급 포인트번호를 입력한 뒤 확정한다.
  신규로 선택한 행에 기존 포인트번호를 쓰면 차단한다. 번호를 자동 생성하지 않는다.
- 연결·값 선택·재검수 후 같은 행의 화면 위치·가로 스크롤·입력 포커스·보기 설정을
  복원한다. 브라우저에는 입력값 대신 위치와 필드 이름만 잠시 보관한다.

## 실제 검증

운영 .env 없는 격리 worktree, uv.lock/Python 3.13, 명시적인 임시 DATABASE_PATH와
합성 자료로 검사한다. 실제 요청서·이름·번호·DB는 공개 증거에 포함하지 않는다.

- 초기 관련 검사에서 새 명시 선택 계약과 종전 덮어쓰기 기대의 차이를 확인했고,
  기존 회귀는 새 HTTP 선택 단계를 거치도록 갱신했다.
- 신규 프로필 선택 HTTP 회귀 15건, 기존 자동·수동 연결 21건 통과. 입력값과 빈 줄 보존,
  미선택 확정 차단, 기존/입력 혼합 선택, 원래 대안 재선택, 초안 재개, 기준 변경 409,
  잔액만 변경된 경우의 선택 유지, 연결 대상 변경, 빈 팀·계급 명시 삭제, 유형 변경 차단,
  서명 누락/변조, 이전 버전 초안, 신규 포인트번호 및 확정 재전송을 확인했다.
- 구버전 Chromium E2E 18건 통과(34.87초). 24명 합성 요청서의 상태 4종·열 순서·집중보기,
  하단 연결/선택 후 세로·가로 위치·포커스·정렬 복원, 기존 33명 자동연결 행 높이를 확인했다.
  첫 실행에서 발견한 모바일 표 헤더의 문서 너비 초과를 수정했고 최종 검사에 통과했다.
- coverage를 켠 200/1,000명×24개월 규모 검사 2건 통과. 1,000명 검수 2.691초/39쿼리,
  저장 1.310초/14쿼리, 대시보드 2.774초/9쿼리, Excel 0.947초/5쿼리였다.
  이후 같은 비교 서명 재사용과 중복 서명 해제 제거로 검수의 중복 처리를 줄였다.
- Ruff check/format(138파일), mypy app scripts(57파일), 빈 임시 DB Alembic upgrade/check,
  pip-audit와 변경 파일 gitleaks 검사 통과. 전체 커버리지는 최종 CI 결과로 연결한다.
- 월간·재검수·초안·동기화 최종 관련 102건 통과(coverage 활성, 부분 실행 기준).
  두 독립 검토에서 추가 차단 결함을 발견하지 못했다.
- 필수 lint/typecheck/test/migrations/security/secret-scan/e2e와 Quality gate는
  PR merge ref 기준 CI에서 확인한다.
