## 변경

- 검수의 월 판정에 이후 월 보정 관측을 포함한다. 처리 월보다 뒤 월의 보정·등록 관측이 있으면
  최대 5명을 `이름(0000 0101, 2026-09)` 형식으로 보여주고 그 월 이상을 선택하도록 안내한다.
  같은 월은 직전 잔액이 관측 시각을 따르므로 계속 허용한다. 정정 경로는 최신 확정 월 이하에만
  삽입하므로 해결책으로 안내하지 않는다.
- 확정 잠금 안에서 대상 인원의 마지막 관측이 처리 월보다 뒤이면 건너뛰지 않고 전체를 되돌린다(409).
- 팀 삭제는 쓰기 잠금·검증 백업 뒤 소속 계정별 전후 정보와 버전 증가를 `팀 삭제`(kind `team`)
  작업으로 기록한다. 백업 실패 시 아무것도 바꾸지 않는다. 없는 팀 삭제는 이력을 만들지 않는다.
- 검수 변경 예상에 "확정 시 새로 만들 팀"을 안내한다. 확인란이 필요한 경고는 아니다.
- DB 스키마·잔액 계산식·Excel 계약은 변경하지 않는다. 사용 안내(`docs/usage-guide.md`)를 갱신했다.

## 실제 검사

운영 환경 파일·DB 없는 worktree, Python 3.13, 명시적인 임시 `DATABASE_PATH`, Mock/합성 자료를 사용했다.

- 재현 검사를 먼저 작성했다. `tests/test_observation_order.py` 5개 중 4개(이후 월 등록·현재 보정
  차단, 확정 방어, 메시지 5명 제한)가 main에서 실패하고 같은 월 허용은 통과했다.
  `tests/test_team_audit.py`의 감사·백업 실패·새 팀 예고 3개도 main에서 실패했다. 수정 후 모두 통과했다.
  차단 시 스냅샷 없음·재직 유지·현재 잔액 (500, 0) 보존·정합성 검사 정상을 함께 확인한다.
- 전체 서버 검사 coverage 94.31%. 전체 동시 실행에서 규모 검사 두 개가 시간 한도를 넘었으나
  쿼리 수는 한도 안이었다. 단독 재실행 2회 모두 통과했고 검수 응답은 main과 같은 1.6초였다.
  검수 SELECT는 39→45(한도 60), 저장은 14→16(한도 20)으로 월 판정·새 팀 조회 각 1회가 늘었다.
- Ruff check/format, mypy app scripts, Alembic upgrade/check 통과.
- 구버전 Chromium 전체 E2E **26 passed**(main 기준, 별도 Compose 프로젝트 실행 후 정리).
- 독립 정적 검토에서 확신 결함은 없었다. 확정 잠금 안의 방어 검사는 검수 단계의 월 판정이 같은
  조건을 먼저 막으므로 보조 장치이며, 재현 검사는 월 판정을 우회해 검증한다.
