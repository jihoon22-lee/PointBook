## 변경

- 개별 원화·외부 기대 총액·인원·실제 연월 검증을 분리했다. 개인 입력에 누락/빈칸/오류 값을
  자동 기본값으로 바꾸지 않고, 최초 관측·음수 순사용·월 공백의 장부 의미를 유지한다.
- 원문 셀·비고·안정 행 ID·이월 입력을 보존한다. 불완전 붙여넣기나 잘못된 번호도 수정 가능한
  행으로 표시하며, 숫자 팀명과 순번이 모호하면 원문/헤더로 확인한다.
- 수정 → 재검수 → 확정 경계를 서버 서명 fingerprint로 검증한다. 목록·월·기대 합계와 전체 DB
  프로필·장부 상태를 연결하며 토큰에는 개인정보 대신 해시만 담는다. 이월 입력은 검수 뒤 채울 수 있다.
- SQLite BEGIN IMMEDIATE 안에서 다시 검수하고 잠금 후 계획·잔액으로 쓰기를 수행한다.
  오류·경쟁·중복 제출을 롤백한다. 삭제한 행의 잔액을 새 비재직 후보에 자동 이전하지 않는다.
- 미래 월·공백·누락 후보·급격한 충전 변화·외부 대사 불일치를 명시적으로 확인받는다.
  기존 공용 누락의 active·잔액 보존과 명시적 신규 공용 유형을 지원한다.
- 전체 대조와 직전 실제 관측 계산의 인원별 반복 SELECT를 일괄 조회로 바꿨다.

- 독립 검토 의견(기대 총액 상한, 누락 유형/월의 자동 추정, 잠금 후 계획 사용, 숫자 팀명 모호성)을
  반영하고 해당 회귀를 추가했다.

## 성능 기준

WSL·Python 3.13.15·SQLite 메모리 DB, 합성 200/1,000명 × 24개월을 같은 환경에서 비교했다.
이름·개인번호 중복을 포함한다. 운영 자료량을 추정한 값이 아니라 개발 대표/여유 규모다.

| 범위 | 기존 분석+잔액 쿼리/초 | 변경 후 쿼리/초 | 전체 검수 쿼리/초 |
|---|---|---|---|
| 200명 | 401 / 0.083 | 2 / 0.013 | 9 / 0.022 |
| 1,000명 | 2,001 / 0.437 | 2 / 0.033 | 9 / 0.077 |

회귀 예산: 분석+잔액 SELECT ≤ 3, 전체 검수 SELECT ≤ 10. 동일 개발 환경에서 1,000명
서버 검수 3초 이내를 후속 비교 예산으로 둔다(실제 Win7 렌더 완료의 측정값이 아님).
자동 테스트는 하드웨어 차이가 적은 쿼리 예산과 결과 정합성을 검사한다.
