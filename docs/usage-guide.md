# PointBook 사용 가이드

소방서 포인트 충전 요청서(엑셀) 관리 서비스의 실사용 가이드.
매달 요청서가 도착했을 때의 일상 업무 흐름을 중심으로 설명한다.

---

## 1. 시작하기 (최초 1회)

### 1-1. WSL에서 설치·초기화

```bash
cd /mnt/e/projects/PointBook
uv sync --group dev                     # 의존성 설치 (최초 1회)
cp .env.example .env                    # 환경설정 파일 생성
```

`.env`에서 다음 값을 반드시 바꾼다:

```ini
ADMIN_USERNAME=admin        # 관리자 아이디
ADMIN_PASSWORD=변경할비밀번호  # 관리자 비밀번호 (반드시 변경!)
SECRET_KEY=긴-임의-문자열      # 세션 서명 키
```

### 1-2. DB 초기화·서버 실행

```bash
uv run python -m scripts.init_db   # 관리자 계정 생성 (최초 1회)
scripts/run.sh                     # 서버 상시 구동 (백그라운드)
```

- 접속: Windows(호스트) 브라우저에서 `http://localhost:8000`
- 중지: `scripts/stop.sh`
- 다른 포트: `PORT=8001 scripts/run.sh`
- **스키마 마이그레이션은 자동**: 서버 기동 시 Alembic이 최신 스키마로 자동 적용한다
  (기존 1.0.x DB는 최초 1회 자동 기준점 설정). 수동으로는 `uv run alembic upgrade head`

### 1-3. 기존 엑셀 데이터 이관 (선택)

기존 요청서 엑셀을 DB로 옮기려면 **인원이 하나도 없는 빈 DB에서** 실행:

```bash
uv run python -m scripts.import_excel --file 기존요청서.xlsx [--month 2026-07]
```

엑셀 헤더는 자동 인식 (팀/부서, 이름/성명, 계급/직급, 금액/충전금액, 개인번호/번호, 포인트번호,
비고/메모, 잔액/이월잔액). 잔액 컬럼이 있으면 이월 잔액으로 기록된다.

여러 달이 가로로 누적된 장부는 별도 명령을 사용한다. 기본 동작은 실제 DB를 바꾸지 않는
dry-run이며, 결과가 모두 맞을 때만 `--apply`를 실행한다.

```bash
uv run python -m scripts.import_ledger --file 누적장부.xlsx --dry-run
uv run python -m scripts.import_ledger --file 누적장부.xlsx --apply
```

실제 `.xlsx`, `data/pointbook.db`, `data/backups/`는 저장소에 커밋하지 않는다. 복구가
필요하면 서버를 중지하고 적용 직전 백업을 `data/pointbook.db`로 복사한다.

## 2. 매달 업무 흐름 (요청서 도착 시)

### 2-1. 요청서 등록

1. **월간 처리** 메뉴 진입
2. **처리 월** 확인 (이번 달이 기본)
3. 다음 중 하나로 요청서 입력:
   - **사진**: 요청서 사진을 파일 선택으로 업로드 → AI가 테이블 인식
     (png/jpg/jpeg/webp/heic, 최대 `MAX_UPLOAD_MB`(기본 10MB))
   - **붙여넣기**: 엑셀/문서에서 표를 복사해 텍스트 영역에 붙여넣기
     (탭·콤마 구분, `순번 팀 이름 계급 금액 개인번호 포인트번호 비고` 순서 — 순번 없이 6~7컬럼도 가능,
     금액에 콤마가 들어가면 탭 구분 권장)
4. **인식 · 검수하기** 클릭

> 사진 인식은 **Gemini**가 동작한다 (`AI_PROVIDER=gemini` + `GEMINI_API_KEY` 설정 필요,
> 서버 재시작 후 적용). 키가 없으면 개발용 Mock이 동작하며, 붙여넣기 방식은 AI와 무관하게 항상 사용할 수 있다.
> 인식 실패 시(흐림·잘린 사진 등) 오류 안내가 표시되며, 붙여넣기로 대체하면 된다.

### 2-2. 검수 화면에서 확인·수정

AI가 뽑은 목록을 눈으로 확인한다:

- **인식된 인원 표**: 포인트번호·개인번호·이름·팀·계급·금액·비고·이월 잔액 수정 가능, 행 추가/삭제 가능
- **변경 예상 (DB 전체 대조)**: 이번 달 처리로 일어날 변화가 색상 배지로 표시
  - 빨강 **신규** — DB에 없던 인원이 요청서에 있음 (재직 추가)
  - 초록 **복귀** — 비재직이었다가 다시 나옴 (재직 전환)
  - 파랑 **재직 유지** — 기존 재직자, `·팀변경` 표시 시 팀 변경
  - 회색 **비재직 전환** — 요청서에 없던 기존 재직자 (타지역 전출로 판단)

### 2-3. 이월 잔액 입력

**처리 대상 전체 인원**(재직 유지·복귀·신규·비재직 전환 모두)의 이월 잔액을 입력한다.
요청서에 있는 인원은 각 행의 **이월 잔액** 칸에, 요청서에서 빠지며 비재직으로
전환되는 인원은 아래의 별도 영역에 입력한다. 포인트번호를 수정하거나 행을 추가해도
잔액은 그 행과 함께 유지된다. 모든 이월 잔액을 입력해야만 확정할 수 있다.

각 입력란에 **직전 총 잔액이 안내**되어 참고할 수 있다. 비재직 전환 대상자도
마지막 잔액을 기록해야 복귀 시 이어서 계산된다. 잔액이 없으면 0을 입력한다.

### 2-4. 확정

**확정 · 동기화** 클릭 (확인 다이얼로그 → 확정). 완료 메시지가 뜨면 끝.

확정 시 한 번에 일어나는 일:
1. 재직 상태 동기화 (신규 추가 / 복귀 전환 / 비재직 처리 / 팀 변경)
2. 인원별 순사용·총 잔액 계산
3. 해당 월 스냅샷 저장

> ⚠️ 같은 월은 한 번만 처리할 수 있다. 확정 후 오류를 발견하면
> "개별 수정"으로 바로잡는다 (아래 3-3).

## 3. 일상 관리

### 3-1. 인원 목록

- **인원** 메뉴: 상태(재직/비재직)·팀 필터, 이름·개인번호·포인트번호 검색
- 각 인원의 **현재 총잔액**을 목록에서 바로 확인
- 이름·포인트번호·개인번호·구분·팀·계급·상태·총잔액 제목을 누르면 오름차순/내림차순 정렬
- 처음에는 재직자를 먼저 표시하고 같은 상태에서는 이름순으로 표시한다. 필터·검색·페이지를
  이동해도 선택한 정렬 기준은 유지된다.
- 인원이 50명을 넘으면 하단에 **페이지네이션**(이전/다음 + 총 인원)이 표시된다
- 이름 클릭 → 개인 상세: 기본 정보 + 월별 포인트 이력(이월/충전/순사용/총잔액)

### 3-2. 인원 추가·수정 (요청서 없이 개별로)

- **인원 추가**: 고유한 8자리 포인트번호와 이름 입력. 일반 인원은 개인번호가 필수이고,
  공용 계정은 개인번호를 비울 수 있다.
- **금액 입력**: 추가/수정 시 **이월 잔액·당월 충전 금액**을 처음부터 입력할 수 있음 (월간 처리 전에도 가능)
- **수정**: 재직↔비재직 전환, 팀 변경, 계급·이름·개인번호·금액 변경
- **삭제는 없다** — 퇴직은 항상 비재직 처리로 관리 (잔액 보존됨)

### 3-3. 개별 잔액 수정 (요청서와 무관한 변동)

**인원 수정 페이지**에서 이월 잔액·당월 충전 금액을 수정한다.
예: 한 명만 추가로 포인트를 충전해준 경우.

- **월간 처리 전**: 인원의 현재 잔액 상태를 수정 (인원 추가 시 입력한 값 포함)
- **월간 처리 후**: 가장 최근 월의 잔액 기록도 함께 수정 — 순사용·총 잔액 자동 재계산
- 인원 상세 페이지에서는 금액을 **표시만** 하며, 월별 이력(이월/충전/순사용/총잔액)을 조회한다
- 순사용 양수는 포인트 순감소, 음수는 적립·이전 등으로 인한 순증가다.
- 월간 처리 확정 시 인원의 현재 잔액도 스냅샷 기록과 함께 자동 갱신됨

### 3-4. 팀 관리

- **팀** 메뉴: 일반 인원을 기준으로 전체·재직·비재직 인원수를 구분해 확인하고, 팀 추가(이름 + **자유 색상 팔레트**)·삭제(소속 인원은 팀 없음으로 변경)
- **팀 이름 클릭 → 팀 상세 페이지**: 재직자를 먼저 표시하며 이름·포인트번호·개인번호·계급·상태·현재 총잔액을 조회. 각 제목을 눌러 오름차순/내림차순 정렬할 수 있고, 인원 이름을 누르면 개인 상세로 이동한다.
- 요청서에 새 팀이 나오면 자동 생성·색상 자동 배정

### 3-6. 설정 — 관리자 비밀번호 변경

- **설정** 메뉴 → 현재 비밀번호 확인 후 새 비밀번호(8자 이상, 확인 일치)로 변경
- 변경 후에는 새 비밀번호로 로그인하면 된다 (로그아웃 없이 즉시 적용)

### 3-5. 대시보드

- **대시보드** 메뉴: 월 선택으로 해당 월 조회
  - 요약 카드: 처리 인원 수 / 총 충전 / 순사용 합계 / 총 잔액
  - 월별 추이 차트: 충전·순사용·잔액 흐름
  - 팀별 통계: 팀 색상 배지로 한눈에
  - 개인별 통계: 컬럼 클릭 정렬, 이름 클릭 → 개인 상세

## 4. 실기기·Win7에서 접속

| 대상 | 방법 |
|---|---|
| Windows(호스트) 브라우저 | `http://localhost:8000` — 별도 설정 불필요 |
| 갤럭시 실기기 | 아래 설정 중 하나 |
| Windows 7 PC (다른 PC) | 아래 설정 중 하나 + `http://<윈도우PC IP>:8000` |

**방법 A — `.wslconfig`** (C:\Users\<사용자>\.wslconfig):

```ini
[wsl2]
networkingMode=mirrored
```

**방법 B — 포트 프록시** (관리자 PowerShell, WSL IP는 `hostname -I`):

```powershell
netsh interface portproxy add v4tov4 listenport=8000 listenaddress=0.0.0.0 connectport=8000 connectaddress=<WSL IP>
netsh advfirewall firewall add rule name="PointBook" dir=in action=allow protocol=TCP localport=8000
```

> 안드로이드 에뮬레이터는 `http://10.0.2.2:8000`.

### 4-1. Tailscale serve 사용 시 주의 (포트 점유)

Tailscale serve(`https://main.tail30f401.ts.net:8002` 등)를 설정하면 **serve 리스너가
백엔드 서버가 죽어도 해당 포트를 계속 점유**한다. stop.sh로 PointBook을 내려도
`scripts/run.sh` 재실행 시 "포트 사용 중" 오류가 날 수 있다.

해결 절차:

```bash
tailscale serve status                  # 원인 확인 (8002 프록시 설정 확인)
tailscale serve --https=8002 off        # 8002 서빙만 해제 (다른 서빙은 유지)
scripts/run.sh                          # PointBook 기동
```

- serve 리스너는 `0.0.0.0:8002` 바인딩과 충돌하므로, **serve를 다시 켤 때는 PointBook을
  127.0.0.1로만 바인딩**해야 한다:
  ```bash
  HOST=127.0.0.1 scripts/run.sh
  tailscale serve --bg https+8002 http://127.0.0.1:8002
  ```

### 4-2. 외부망(매장 PC 등) 접속 — Tailscale Funnel

현재 설정(Tailscale serve)은 tailnet 내부 전용이라, **외부망에 있는 매장 PC는 접속할 수 없다.**
외부망에서 접속하려면 Tailscale **Funnel**로 서비스를 공개한다 (매장 PC에 설치 불필요, 브라우저만):

```bash
tailscale funnel --bg 8002    # 127.0.0.1:8002를 공개 노출 (443 포트)
tailscale funnel --bg --https=8443 8002   # 8443 포트로 공개 (원하면)
```

**해제**:
```bash
tailscale funnel reset              # Funnel 전체 해제 (가장 확실)
tailscale funnel --https=443 off    # 특정 포트만 해제 (다른 공개 유지)
tailscale serve --https=8002 off    # serve(내부 전용) 특정 포트 해제
tailscale funnel status             # 공개 상태 확인
```

- 접속 URL: `https://main.tail30f401.ts.net` (443) 또는 `https://main.tail30f401.ts.net:8443`
- **Funnel 공개 포트 제약**: HTTPS는 **443·8443·10000만** 지원 — 내부와 동일한 8002 포트로 외부 공개는 불가능
- 첫 사용 시 `tailscale funnel status`가 관리 콘솔 승인 링크를 안내 (1회)
- 기존 tailnet 전용 주소(`:8002`)는 그대로 유지됨

**도메인 변경**:
- 머신 이름 부분은 변경 가능: `tailscale set --hostname=pointbook` → `pointbook.tail30f401.ts.net`
  (변경 시 기존 즐겨찾기 URL도 새 이름으로 바뀜)
- tailnet 접미사(`tail30f401.ts.net`)는 변경 불가. 자기 도메인 소유 시 admin console에서 커스텀 도메인+HTTPS 인증서 설정 가능

**내부와 동일한 포트(8002)가 꼭 필요하면**: 매장 PC에 **ZeroTier**(Win7 지원)를 설치해 가상 사설망 구성 —
`http://<가상IP>:8002`로 내부와 동일한 포트 접속 가능 (양쪽 설치·가입 필요)

**주의**:
- Funnel은 **완전 공개** — URL을 아는 누구나 접근 가능. 관리자 비밀번호를 강력하게 유지할 것
- Win7 구형 업데이트 미적용 PC는 Let's Encrypt 인증서 신뢰 문제 가능 (인증서 경고 시 Windows 업데이트/ESU 적용 필요)

## 5. 주의사항·팁

- **비밀번호는 `.env`로 관리** — 파일 공유·커밋 금지 (`.env`는 gitignore 처리됨)
- **DB 백업은 자동**: 월간 확정 시 `data/backups/`에 자동 백업된다 (보관 개수 `BACKUP_KEEP`, 기본 30).
  수동 백업은 `uv run python -m scripts.backup`, 복구는 서버 중지 후 백업 파일을 `data/pointbook.db`로 복사
- **확정 전 검토**: 변경 예상 배지로 비재직 전환 대상자를 꼭 확인 — 요청서에
  누락된 인원이 있으면 자동으로 비재직 처리되므로, 실수 시 개별 수정으로 복구
- **금액 표기**: `50,000원`처럼 콤마 포함 입력도 가능 (숫자만 추출)
- **검수 화면의 이월 잔액**: 인원 행에 연결되므로 포인트번호를 수정하거나 행 순서를
  바꾸어도 해당 잔액이 다른 인원에게 적용되지 않는다. 빈칸이 있으면 확정이 거부된다.
- **모바일**: 표가 넓은 화면은 좌우 스와이프로 스크롤
- **로그인 잠금**: 비밀번호를 여러 번 틀리면 일정 시간 로그인이 잠긴다 (브루트포스 방지)

## 6. 실사용 테스트 체크리스트

집에서 실사용 테스트할 때 아래 순서로 확인하면 좋다:

- [ ] 로그인/로그아웃 (아이디·비밀번호, 틀린 비밀번호 오류)
- [ ] 인원 추가 → 목록·상세 표시
- [ ] 팀 추가(자유 색상 팔레트) → 인원에 팀 배정
- [ ] 월간 처리: 붙여넣기 → 검수(변경 예상 확인) → 이월 잔액 입력(직전 잔액 안내) → 확정
- [ ] 확정 후 인원 상세에서 월별 이력·사용·총잔액 계산 확인
- [ ] 비재직 전환 대상자가 정확히 잡히는지 (요청서에 안 넣은 기존 재직자)
- [ ] 복귀자 잔액이 이어지는지
- [ ] 개별 잔액 수정 후 재계산 확인
- [ ] 대시보드: 월 선택, 요약 카드, 추이 차트, 팀별·개인별 표, 정렬
- [ ] 사진 업로드 (실제 요청서 사진, `AI_PROVIDER=gemini` 설정 시 Gemini 인식 — 검수 화면 확인)
- [ ] 팀 탭: 팀 클릭 → 소속 인원 목록 → 인원 클릭 → 개인 상세
- [ ] 팀 추가 시 자유 색상 팔레트 선택
- [ ] 엑셀 이관 (기존 파일로 빈 DB 시험)
- [ ] 설정: 관리자 비밀번호 변경 (현재 비밀번호 확인 → 새 비밀번호 → 재로그인)
- [ ] 월간 확정 후 `data/backups/`에 백업 파일이 생성되는지 확인
- [ ] 인원 50명 초과 시 목록 페이지네이션 동작
- [ ] 인원·팀원 목록의 모든 정보 열 정렬과 인원 총잔액 표시
- [ ] 갤럭시 실기기: 모바일 화면 전 페이지 확인, 탑바·표 스크롤
- [ ] Win7 Chrome 109: 접속·로그인·주요 흐름 (IE11은 안내 페이지 대상)
