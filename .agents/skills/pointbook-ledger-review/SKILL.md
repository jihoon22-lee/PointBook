# PointBook 장부 검토

입력은 대상 diff 또는 설계와 관련 요구사항이다. [루트 지침](../../../AGENTS.md)과
[요구사항 #48](https://github.com/jihoon22-lee/PointBook/issues/48)을 기준으로 검토한다.
설계 계약과 실제 구현·실행 검증을 구분한다. 검토 요청만으로 코드를 수정하거나 DB를 쓰지 않는다.

## 변경 경로를 따라 확인

- 포인트번호 정규화와 선행 0을 보존하는가? 이름·개인번호가 같은 계정을 합치지 않는가?
- 요청서에 없는 기존 재직 일반 계정까지 대조하는가? 공용계정은 누락돼도 active이며
  개인번호 NULL·팀 없음이 허용되는가? 비재직·미관측 잔액이 사라지지 않는가?
- 충전액·이월액의 0 이상 정수 계약과 부호 있는 순사용을 구분하는가?
  최초 관측의 순사용은 0이며 이후에는 바로 이전 달이 아닌 직전 **실제 기록**을 찾는가?
- 과거 total 변경은 다음 실제 기록의 usage에 반영되는가? 다음 기록의 입력 carry/amount를
  근거 없이 바꾸지 않는가? 최신 기록이 달라지면 현재 잔액과 일치하는가?
- 프로필 변경이 과거 금액·비고와 원본 감사 자료를 덮어쓰지 않는가? 이름·번호·팀·계급은
  과거 월의 화면·보고서·Excel에도 현재 인원 정보를 쓰는가? 월별 별도 인원 정보 관리를 만들지 않는가?
  정정 전후·사유·기준 버전·감사 이력과 오래된 탭의 충돌을 처리하는가?
- 검수 후 행 삭제·식별자 변경·월 변경·DB 변경 시 입력 보존과 재검수 대상이 맞는가?
  확정의 중복 제출이 이중 반영이나 부분 커밋을 만들지 않는가?
- 월 활동 합계와 기준 시점 보유 잔액을 구분하고 화면·보고서·Excel이 같은 집계 계약을 쓰는가?
  개별 등록·복귀 후의 실제 월간 비재직 전환을 누락하지 않는가? 과거 월 추가는 지급액으로
  월별 상태를 판정하며 현재 재직 상태를 바꾸지 않는가? 여러 줄 비고가 검수·초안·정정·Excel에 보존되는가?
- 이전·복원은 합성 DB로 전후 행·합계를 대사했는가? 운영 자료를 임의 읽기·반출하지 않고,
  운영 쓰기에는 승인과 검증된 백업이 있는가? 쓰기 재개 후 자동 전체 rollback을 하지 않는가?

## 계산 검증용 합성 사례

변경과 관련 있는 사례를 선택하고 기존 테스트가 있으면 재사용한다.

- 1월 total 100,000, 2월 미관측, 3월 carry 70,000/amount 50,000이면
  3월 usage 30,000, total 120,000이다. 2월 기록을 생성하지 않는다.
- 1월 total을 110,000으로 정정하면 3월 usage는 40,000이다.
  3월 carry/amount/total은 그대로이며, 최신 기록이 3월이면 현재 잔액도 120,000이다.
- 직전 total 100,000, 이번 carry 120,000이면 usage -20,000을 보존한다.
- 첫 관측은 carry가 있어도 usage 0이다. 장기 비재직 후 복귀는 직전 실제 기록에서 계산한다.
- 같은 이름·개인번호에 서로 다른 8자리 포인트번호, 개인번호 없는 공용계정,
  요청서 누락 일반 계정과 공용계정을 함께 넣어 모집단·상태·합계를 확인한다.

## 결과

재현 조건 → 실제 영향 → 파일/라인 → 관련 R/S → 실행한 검증 순으로 중요한 결함을 보고한다.
증거 없는 가정은 확인 필요로 구분한다. 계획된 정정 기능이 없다는 이유만으로 관련 없는
준비 PR에 기능 전체를 요구하지 않는다. 발견 없음과 미검증을 구분하고, 테스트·실기·운영 대사의
미실행을 PASS로 표시하지 않는다. 공개 예시는 합성 데이터만 사용한다.
