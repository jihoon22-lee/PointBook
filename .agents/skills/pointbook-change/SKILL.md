# PointBook 변경 작업

입력은 사용자의 변경 요청과 해당 이슈다. 출력은 요청 범위의 변경, 실제 검증 결과,
리뷰 가능한 설명이다. [루트 지침](../../../AGENTS.md)의 업무·권한 경계를 따른다.

## 범위와 구현

- v1.4.0 작업이면 #47·#48·대상 WP와 현재 main/로컬 변경을 확인한다.
  요구사항 R/S와 해당 코드·테스트를 연결하고 이번 작업에서 완료할 범위를 정한다.
  준비 작업은 B01~B04 구현 완료로 기록하지 않는다.
- 변경이 복잡하면 필요한 결정·검증을 짧게 계획한다. 이미 승인된 계획을 다시 쓰거나
  사용자에게 같은 선택을 반복해서 묻지 않는다. 단순 수정에는 별도 설계 문서를 만들지 않는다.
- 실패를 합성 fixture로 재현하고 기존 서비스 경계 안에서 수정한다. 값의 입력·검수·확정·조회
  경로를 따라가며, UI에서만 검증하지 말고 실제 HTTP 요청 경계를 확인한다.
- DB 작업은 운영 환경 파일 없는 worktree와 임시 DB를 사용한다. 구체적인 실행 방법은
  [개발 안내](../../../docs/agent-workflow.md#격리된-개발과-검증)를 읽는다.

## 검증 선택

아래에서 변경과 관련 있는 검증을 선택한다. 모든 행을 매번 실행하는 체크리스트가 아니다.

| 변경 | 먼저 확인할 경로 |
|---|---|
| 금액·월·행 입력 | `tests/test_monthly.py`, `tests/test_dates.py`, 실제 HTTP 폼의 빈칸/0/오류 원문 보존 |
| 검수·확정 | `tests/test_sync.py`, `tests/test_monthly.py`, 행·포인트번호·월 변경 후 재검수와 중복/오래된 제출 |
| 잔액·집계·역사 | `tests/test_balance.py`, `tests/test_dashboard.py`, 관련 이관 테스트와 장부 검토 skill |
| 인증·AI | `tests/test_auth.py`, `tests/test_security.py`, `tests/test_gemini.py`; Mock·실패 응답 사용 |
| DB·백업·배포 | `tests/test_migrate.py`, `tests/test_backup.py`, 배포 스크립트 테스트, 임시 DB Alembic·격리 Compose smoke |
| HTML·JS·업무 흐름 | 관련 라우터 테스트와 구버전 Chromium E2E; Win7/Android 실기는 별도 판정 |
| CI·개발 설정 | 바뀐 명령을 실행하고 게이트 실패·건너뜀 조건을 검증 |

파일 목록은 현재 저장소에서 다시 확인한다. 통과 이후 검사 확대·반복은 새 변경이나
남은 우려로 정당화한다. PR의 필수 CI·커버리지 기준을 줄이지 않는다.

## 검토와 인계

- 변경 diff를 요구사항과 대조한다. 장부 계산·집계·이관을 바꿨다면
  [장부 검토](../pointbook-ledger-review/SKILL.md)의 관련 사례를 확인한다.
- PR 묶음의 workthrough 하나에 중요한 결정·관련 R/S/WP·실제 명령/결과·미실행을 기록한다.
  PR·검증 SHA·CI URL을 연결하되 기록 자체 커밋의 SHA를 같은 파일에 넣으려 반복 커밋하지 않는다.
  최종 커밋의 검증은 CI URL로 연결할 수 있다.
- PR에는 문제와 바뀐 동작, 검증, 남은 한계를 한글로 설명한다. 완료하지 않은 WP나
  상위 #47/#48에 `Closes`를 붙이지 않는다. 이슈 진행은 실제 결과만 반영한다.
- 현재 요청의 게시·머지 권한과 루트 워크플로를 따르고, 문서 작성만으로 새 외부 게시
  권한을 추론하지 않는다. 추가 승인이 필요하면 준비된 결과를 제시한다.
